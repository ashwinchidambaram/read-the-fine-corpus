## Verified Sound

The following design elements are well-specified and require no remediation from an operability standpoint:

- **Service decomposition and responsibilities** (ADR-0005, overview.md): the five-service model, library boundary, import-linter enforcement, and constraint enforcement table (C-1 through C-5) are clearly articulated and show how each hard architectural constraint is mechanically enforced, not just stated.
- **Index lifecycle state machine** (index-lifecycle.md): the Mermaid state diagram with named states, labelled transitions, and preconditions is the best-specified section in the package. An operator can read it and understand what the system is doing at any point during ingestion or promotion.
- **Data contracts** (contracts/*.md): all six contracts are specified with full field tables, invariants, open questions with proposed defaults, and golden-corpus expressibility checks. The `schema_version` and semver compatibility rules are rigorously designed. The `TenancyBlock`, `SourceLocation`, `TransformationRecord`, and `Provenance` shared blocks are defined once and reused consistently — a self-hoster reading a chunk payload will find the field semantics in one place.
- **Chunk identity and determinism** (ADR-0006, chunk.md): the five-field canonical string, the sha256-to-base32 derivation, the UUID mapping for Qdrant point IDs, and the worked example covering all three edit cases are clearly specified. A self-hoster debugging orphan detection or incremental update correctness has everything they need.
- **Provider abstraction** (provider-abstraction.md): the capability-declaration model, the `estimate_cost` pure-function requirement, the model-identity pinning fields, the mismatch-check protocol, and the air-gap enforcement (`RTFC_AIRGAP=true` blocks outbound HTTP before any call is made) are all well-designed with clear operator-facing behaviour.
- **Segment taxonomy** (segment-taxonomy.md): 14 types (13 content types + 1 sentinel) with definitions, concrete examples, and default handling notes; 4 salience tiers with precedence-ordered signal matrix; golden-corpus fixture coverage mapping; and explicit findings on gaps (F-1, F-2). Open questions are flagged with proposed defaults, not resolved silently.
- **MUST traceability structure** (must-traceability.md): the 105-row matrix exists and is correctly derived from the spec. The tracking schema (Design ref, Phase, Test layer, Status) is the right instrument — it just needs to be filled in.
- **Decision ledger** (decision-ledger.md): all nine spec open decisions are present with statuses. Closed decisions link to ADRs. Open decisions state the phase they are needed by. The process for moving PROPOSED to CLOSED is documented.
- **Internal LLM configuration** (provider-abstraction.md §4.2): the YAML configuration block with per-operation overrides, the content-as-data prompt discipline, and the schema-validation requirement are specified with enough detail for a self-hoster to understand how to configure and audit internal model calls.
- **Cost estimation hooks in contracts** (provider-abstraction.md §2.2, ingestion-config.md): the `estimate_cost` method is a pure function in the provider interface; `RecommendationProvenance` carries a `sweep_run_id` and `basis` to distinguish heuristic from evidence-backed recommendations. The §16 "estimate before execute" requirement has a clear design hook in both the provider layer and the config contract.
- **Failure semantics mapped to state machine** (index-lifecycle.md §6): every §15 failure row is explicitly mapped to a state transition, which state it enters, and the required behaviour. This is sufficient for an operator to understand what the system will do under each failure mode even before runbooks exist.
- **Air-gap enforcement** (provider-abstraction.md §7.2, §7.3): `RTFC_AIRGAP=true` is a named environment variable; `is_local: true` on all providers is the gate; the health check confirms Ollama endpoint reachability on the local network; the first-run prompt handles Ollama setup without egress. The air-gap path is first-class, not a degraded fallback. (The single gap at OQ-P-5 pricing-fetch is called out above as O-R9.)
